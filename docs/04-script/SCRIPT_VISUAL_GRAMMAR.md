# Script ↔ Visual Grammar

## Core Principle

Civilization X-Ray의 핵심 자산은 대본 자체도, 3D 자체도 아니다.

> **한 문장의 의미를 어떤 시각 행동으로 바꿀지 결정하는 반복 가능한 문법**이 핵심이다.

따라서 대본과 콘티를 분리된 산출물로 만들지 않는다.

최소 단위:
`claim / narration sentence ↔ visual proof / camera action / evidence state`

---

# Long-form Narrative Spine

기본 길이: 8–15분, 주제에 따라 가변.

## Beat 0 — Cold Open / Visual Contradiction
0:00–0:20 권장.

목적:
- 설명하려는 대상보다 “이상한 점”을 먼저 보여준다.

예:
- 바다 위 도시를 보여준 뒤 수면 아래로 내려가며 “이 무게를 진흙이 버티고 있다면 이미 가라앉았어야 합니다.”

금지:
- 긴 채널 인사
- 백과사전식 연도/높이 소개
- 답을 전부 먼저 말하기

## Beat 1 — Question Lock
약 0:20–0:45.

시청자가 끝까지 봐야 알 수 있는 핵심 질문을 한 문장으로 고정한다.

좋은 질문:
- 한 가지 mechanism에 집중
- 화면으로 증명 가능
- 실제 답이 단순 trivia가 아님

## Beat 2 — Scale & Constraint
대상이 해결해야 했던 물리적/도시적/역사적 문제의 규모를 보여준다.

시각 행동:
- 사람/자동차/축구장 등 scale reference
- 하중/물/바람/거리/깊이 overlay
- map → object transition

## Beat 3 — Wrong Intuition / Surface Explanation
시청자가 자연스럽게 떠올릴 오해 또는 불충분한 설명을 짚는다.

목적:
- 정보 전달이 아니라 “왜 X-Ray가 필요한지” 만든다.

## Beat 4 — First X-Ray Reveal
첫 핵심 보상.

시각 행동:
- shell removal
- ground cutaway
- exploded view
- transparency
- flow reveal

이 지점에서 채널의 시각적 정체성이 가장 강하게 드러나야 한다.

## Beat 5 — Mechanism Chain
2–4개의 원인 단위로 나눈다.

각 단위:
1. 문제
2. 구조/장치
3. 작동
4. 결과
5. 다음 문제로 연결

한 번에 하나의 공간/물리 개념만 설명한다.

## Beat 6 — Human / Historical Constraint
기술을 만든 사람, 시대, 재료, 비용, 공사 제약을 연결한다.

역사 에피소드에서는 비중을 늘리고 현대 시스템에서는 짧게 쓸 수 있다.

## Beat 7 — Stress Test / Counterfactual
가능하면 “이게 없다면?”을 보여준다.

예:
- 특정 구조를 제거
- 바람 방향 변경
- 배수량 증가
- 잘못된 경사 적용

목적:
- mechanism을 관객이 직관적으로 검증하게 한다.

## Beat 8 — System Reassembly
분해했던 구조를 다시 전체로 조립한다.

시청자가 이제 첫 장면을 다르게 볼 수 있어야 한다.

## Beat 9 — Payoff
Cold Open 질문에 정확히 답한다.

새로운 핵심 사실을 갑자기 추가하지 않는다.

## Beat 10 — Residual Wonder
다음 에피소드와 연결 가능한 더 큰 질문 또는 인간 규모의 의미를 짧게 남긴다.

# Four Script Structures

## S1. Mystery Reveal
가장 범용.

`paradox → intuition → x-ray reveal → mechanism chain → proof → payoff`

Best for:
- 건축 구조
- 베네치아 기초
- 초고층 바람

## S2. Journey

`origin → path → stage 1 → bottleneck → stage 2 → destination → zoom out`

Best for:
- 수도
- 하수
- 공항 수하물
- 전력

## S3. Build the Impossible

`goal → constraints → failed/simple options → construction sequence → key innovation → completion`

Best for:
- 고대 공학
- 해저 터널
- 대형 교량

## S4. Failure Test

`normal state → stress → weak point → propagation → safeguards → lesson`

Best for:
- 교량
- 댐
- 고층 구조

Decision:
- S1을 채널 기본 문법으로 사용.
- 에피소드 타입에 따라 S2/S3/S4를 선택.
- 모든 영상에 S1을 강제하지 않는다.

# Visual Action Taxonomy

대본 작성자는 각 핵심 문장에 아래 action 중 하나 이상을 연결한다.

## A. Reveal Actions
- CUTAWAY: 외피/지면 절개
- TRANSPARENCY: 외피 투명화
- EXPLODE: 구성요소 분리
- LAYER_PEEL: 층을 순차 제거
- INSIDE_FLYTHROUGH: 내부로 진입

## B. Relationship Actions
- CONNECT: 구조 연결 표시
- LOAD_PATH: 힘 전달 경로
- FLOW_PATH: 물/공기/사람/열 이동
- SIGNAL_PATH: 신호/명령 전달
- BEFORE_AFTER: 상태 비교

## C. Scale Actions
- HUMAN_SCALE
- CITY_SCALE
- DISTANCE_TRACE
- DEPTH_REVEAL
- QUANTITY_MULTIPLY

## D. Causal Actions
- REMOVE_COMPONENT
- ADD_LOAD
- CHANGE_PARAMETER
- FAILURE_PROPAGATION
- SAFEGUARD_ACTIVATION

## E. Temporal Actions
- BUILD_SEQUENCE
- AGE_TRANSITION
- HISTORICAL_RECONSTRUCTION
- MODERN_OVERLAY

## F. Orientation Actions
- ORBIT
- TOP_DOWN
- SECTION_LOCK
- AXIS_TRACE
- MAP_TO_OBJECT
- OBJECT_TO_DETAIL

# Sentence Classification

대본 문장을 먼저 분류한다.

1. CLAIM — 검증 가능한 사실 주장
2. EXPLANATION — 원리 설명
3. ORIENTATION — 공간/시간 위치 안내
4. SCALE — 규모 이해
5. TRANSITION — 다음 개념 연결
6. DRAMA — 긴장/역사적 맥락
7. QUALIFIER — 불확실성/예외/한계
8. PAYOFF — 질문의 답

### Rule
CLAIM / EXPLANATION 문장은 가능한 한 visual proof와 source lineage를 가진다.
TRANSITION만 계속되거나 DRAMA가 연속으로 길어지면 정보 밀도가 낮아진다.

# Script ↔ Visual Row Contract

각 핵심 unit는 이후 하네스에서 다음 필드를 가져야 한다.

- `unit_id`
- narration intent
- sentence class
- claim ids
- visual objective
- visual action(s)
- subject / hero object
- camera start
- camera end
- continuity locks
- evidence level
- reconstruction label if needed
- expected duration
- transition in/out
- fallback visual

실제 데이터 포맷은 구현 단계에서 정한다. Phase 0에서는 필드 의미만 고정한다.

# Hook Rules

좋은 hook:
- 화면에서 즉시 이상함을 보여준다.
- 질문이 구체적이다.
- 답이 5초짜리 trivia가 아니다.
- 영상의 실제 핵심과 일치한다.

나쁜 hook:
- “여러분은 알고 계셨나요?”
- 사실을 과장하거나 절대화
- 본문에서 다루지 않는 거대한 약속

첫 30초 성공조건:
1. 대상 인식
2. 문제/모순 인식
3. 왜 궁금해야 하는지 이해
4. 최소 한 번의 visual transformation

---

# Information Density Rule

한 컷에서 새 spatial concept는 기본 1개.

예외:
- recap
- final reassembly

시청자가 구조를 읽어야 하는 컷은 narration pacing을 낮춘다.

“말로 세 문장 설명 + 화면은 계속 움직임”을 피한다.

---

# Uncertainty Language

확정:
- “~이다 / ~한다”

강한 근거의 추론:
- “자료를 종합하면 ~로 보는 것이 가장 타당하다”

역사적 재구성:
- “정확한 과정은 남아 있지 않지만, 당시 기술과 자료를 바탕으로 이렇게 재구성할 수 있다”

설명용 단순화:
- “이해를 위해 구조를 단순화해 보면”

화면의 realism 수준이 근거의 certainty를 초과하지 않도록 한다.

---

# Ending Rule

좋은 결말은 새로운 trivia가 아니라 **처음 보인 대상을 다시 보여주되 시청자가 이제 내부를 상상할 수 있게 하는 것**이다.

Recommended final visual:
- exploded/cutaway 상태 → 천천히 재조립 → 실제/전체 view

Narration:
- 질문에 한 문장 답
- 구조가 해결한 인간 문제 한 문장
- 필요 시 다음 질문 한 문장
