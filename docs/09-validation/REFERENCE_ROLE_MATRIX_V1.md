# Reference Role Matrix V1

Status: **Empirical reference refinement — no architecture change**
Date: 2026-08-15

## Purpose

Civilization X-Ray의 reference strategy를 한 채널에 과도하게 의존하지 않도록 역할을 분리한다.

핵심 결론:

> **`신비한 건축사전`은 topic packaging / hook / compressed mechanism grammar의 핵심 레퍼런스다. 8–15분 long-form pacing의 단독 benchmark로 쓰지 않는다.**

현재 공개 지표에서 이 채널은 short-form 중심으로 관측되므로, long-form에서는 다른 레퍼런스가 담당해야 한다.

- public analytics index는 YouTube 자체 정본이 아니며 지표가 시점별로 변할 수 있다.

- exact frame cadence, shot duration distribution, camera choreography는 아직 `UNOBSERVED / PARTIAL`이다.

# 3. Title / Hook Grammar — Evidence Level

## VERIFIED / strong public evidence

Repeated high-signal title forms include:

### G1 — Quantified Constraint
`large number / extreme duration / extreme scale + mechanism`

Purpose:
- makes invisible engineering cost legible

Risk:
- fake precision if number is weakly sourced

### G2 — Counter-Intuition
`what people assume is not the actual cause`

Purpose:
- creates an information gap immediately

Risk:
- contrarian clickbait if the rejected intuition is straw-manned

### G3 — Impossible Condition
`this system should not work under ordinary intuition`

Purpose:
- establishes the central question before historical background

Risk:
- exaggerating “impossible” beyond the engineering reality

### G4 — Hidden Fix
`famous structure/system + surprising internal workaround`

Purpose:
- high X-Ray value because the answer is visually hidden

Risk:
- reducing a multi-factor system to one trick

# 4. Reference Role Split

No single reference should own all dimensions.

## A. 신비한 건축사전

Use for:
- Korean audience topic packaging
- short-form hook density
- counter-intuitive mechanism framing
- title promise structure
- rapid causal escalation

Do NOT use as sole authority for:
- 8–15 minute pacing
- long-form chapter architecture
- frame cadence until direct frame corpus exists
- production tool inference

Role:
`PACKAGING + MECHANISM COMPRESSION REFERENCE`

---

## B. Practical Engineering

Official positioning observed:
- civil engineering
- public works / infrastructure
- constructed world
- explanations using engineering concepts and demonstrations

Use for:
- long-form causal clarity
- engineering explanation hierarchy
- how physical constraints are introduced before consequences
- demonstration/diagram logic
- infrastructure audience trust

Do NOT copy:
- host identity
- demonstration style as mandatory channel identity
- exact episode structure

Role:
`LONG-FORM ENGINEERING EXPLANATION REFERENCE`

# 7. Benchmark Evidence Classes

Every future benchmark observation should be tagged:

- `OBSERVED_DIRECT` — directly watched/read from original source
- `OBSERVED_PUBLIC_INDEX` — public metadata/index result
- `OBSERVED_REPOST` — public repost or quoted fragment
- `INFERRED` — inference from supported observations
- `UNOBSERVED` — not verified

Rule:
`INFERRED` cannot be silently promoted to `OBSERVED_DIRECT`.
