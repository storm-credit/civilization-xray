# Governance & Shared Services

Status: **Cross-cutting design — no implementation code**

## Why This Is Not Another Orchestra

Fact checking, rights, QA, memory and asset registries cut across every creative domain. Making them another creative orchestra would blur reject authority and create unnecessary handoffs.

Therefore Civilization X-Ray uses:

1. **Fact / Rights / Quality Governance Plane** — independent verdicts
2. **Shared Asset & Memory Service** — versioned registries and retrieval

---

# 1. Fact Governance

Checks:
- claim/source lineage
- qualifier survival from script to final edit
- numbers/units
- causal overstatement
- reconstruction status
- title/thumbnail claim strength

Critical factual FAIL cannot be overridden by a creative director.

---

# 2. Rights Governance

Covers:
- source images/video
- 3D models
- textures/fonts where relevant
- generated images/video
- music
- SFX
- voice/TTS assets
- commissioned assets
- required credits/attribution

Minimum rights state:
- asset ID
- source/provider
- acquisition/creation date
- terms/license review date
- commercial-use status
- modification status
- attribution requirement
- restrictions/unknowns
- usage episodes

Unknown critical right => BLOCK.

---

# 3. Quality Governance

Independent verdict dimensions:
- factual integrity
- script ↔ visual alignment
- spatial/object continuity
- semantic continuity
- temporal/era continuity
- narration intelligibility
- audio mix quality
- caption correctness
- editorial pacing/clarity
- packaging integrity
- rights/provenance

Averages are forbidden for critical gates. One critical FAIL is still FAIL.

---

# 4. Shared Asset & Memory Service

Registry groups:

## Constitution / Channel
- project rules
- channel DNA
- content scope
- audience assumptions

## Editorial
- source index
- claim patterns
- glossary
- pronunciation dictionary

## Visual
- Spatial/Asset Bible library
- reusable Blender assets
- camera rig library
- visual motifs
- 2D templates
- Veo prompt lessons

## Audio
- Voice Bible
- Sonic Bible
- music motif registry
- approved music/SFX assets
- mix lessons

## Production
- prompt versions
- tool/model capability observations
- failure/recovery patterns
- cost observations

## Release/Learning
- packaging experiments
- analytics findings
- approved Channel DNA updates

---

# 5. Memory Promotion Rules

Episode finding does not automatically become channel memory.

Promotion states:
1. Episode observation
2. Candidate lesson
3. Repeated evidence / explicit expert confirmation
4. Approved channel rule
5. Superseded/deprecated when contradicted

Every promoted rule should preserve why it exists and what evidence supported it.

---

# 6. Asset Reuse Rules

Reuse requires:
- current approved status
- relevant rights still valid/understood
- no superseding asset
- compatibility with current Spatial/Sonic/Voice Bible
- no hidden factual assumptions from the old episode

Published once ≠ approved forever.

---

# 7. Independence Rules

At minimum, keep independent review contexts for:
- Claim Verification
- Final Fact/Rights verdict
- Visual QA when creator produced the same shot

Music/SFX creators cannot self-approve unresolved rights status.
Packaging cannot self-approve factual escalation.

---

# 8. Escalation

Escalate to Project Orchestrator/human when:
- credible sources conflict on a central claim
- commercial rights unclear
- period reconstruction has multiple materially different interpretations
- a creative improvement requires changing a locked factual qualifier
- budget pressure would require bypassing a critical QA gate
- analytics recommendation conflicts with channel constitution

---

# 9. Success Criteria

Governance/shared services are sufficient when the project can answer:
- Why do we believe this claim?
- Why is this shot shaped this way?
- Which version of the model/script/voice/music was used?
- Can we commercially use each important asset?
- Which agent/director approved this stage?
- What changed after publication, and why?
- Is this lesson episode-specific or channel-level?

If those questions cannot be answered, the blackboard/registry design is incomplete.
